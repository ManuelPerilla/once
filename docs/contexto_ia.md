# Contexto breve de ONCE

ONCE explora datos de fútbol, inicialmente Colombia, con identidad azul noche, lima y blanco. Se trabaja y ejecuta con Docker local; GitHub es opcional. La carpeta es `once`; Compose mantiene el proyecto `vertice` y sus volúmenes para conservar la instalación existente. No se renombran volúmenes por cambiar la marca.

El objetivo operativo es alimentación automática y administradores dedicados a excepciones. Ya existen un trabajador independiente, cola persistente, cuotas, pausa global/por ámbito, recuperación, observaciones y notificaciones SSE. La navegación consulta datos locales; no descarga proveedores por visitante. Una instalación nueva empieza pausada. El descubrimiento prepara perfiles candidatos pausados, y el calendario adapta la cadencia a estado/fecha con límites de cuota e intervalo; los datos de liga/equipos tienen una ventana de reutilización.

Wikidata/Commons aportan identidad, hechos verificables y escudos; el archivo abierto disponible se presenta como histórico. API-Football ya está conectado y fue comprobado con una cuenta Free el 27 de septiembre de 2026. La fuente indicó acceso a 2022–2024 y un límite de 100 consultas diarias; rechazó 2026. Su catálogo colombiano incluye Primera A, Primera B, Copa Colombia, Liga Femenina y Superliga. En el piloto ya se importaron calendarios reales y se completa el detalle progresivamente: Free admite un partido por consulta, por lo que completar el archivo puede requerir varios días. No afirmar que todas las temporadas o estadísticas están cargadas ni presentar este plan como seguimiento en directo de 2026.

El panel de conexión muestra suscripción, cuota observada y temporadas permitidas. Leerlo no consulta al proveedor; comprobar la cuenta es una acción explícita con presupuesto. Preparar competiciones conserva las decisiones de modo existentes, y activar la selección no cambia el control general. Las clasificaciones de la fuente se asocian a edición, fase y grupo tras verificar participantes. Una coincidencia de nombre genera revisión, no fusión automática.

Las identidades externas incluyen contexto. Hay participantes por edición/fase/grupo, marcador desconocido distinto de cero, correcciones protegidas por campo, historial con actor y cuentas nominales por perfil. Las tablas ONCE usan reglas versionadas y se separan de las publicadas por una fuente. Los reglamentos colombianos concretos y sus promedios necesitan evidencia y capacidades verificadas antes de activarlos.

La demo sigue aislada mediante `?demo=1`. Se preservan navegación móvil, legibilidad y etiquetas comprensibles. Los registros manuales y el historial previo de OpenFootball se conservan; no se borran ni se reclasifican para aparentar cobertura del proveedor. Las fichas públicas distinguen «Registro manual», «API-Football» y «Archivo abierto»; sin procedencia confirmada muestran «Origen sin confirmar». Las herramientas técnicas se traducen a acciones de traer información, revisar, corregir y controlar la automatización.

Antes de modificar, consulta la [arquitectura](architecture.md), el [modelo real](data.md), [automatización](automation.md), [dominio y auditoría](automation/domain-and-audit.md), las [pruebas](development.md) y los [manuales de despliegue](deployment/local.md). Los [hitos](hitos.md) distinguen código implementado, verificaciones efectuadas y cobertura pendiente. La [propuesta original](proposals/sincronizacion-colombia.md) conserva criterios de aceptación y una matriz de situación; sus ambiciones futuras no son pruebas de capacidad actual.

Existe un [manual de servidor con dominio y HTTPS](deployment/server.md). Es una ruta de despliegue y no significa que la instalación local ya se haya publicado en Internet. Las credenciales permanecen en la configuración privada del servidor y deben compartirse con API y trabajador; nunca se incorporan al frontend.

Nunca ejecutes pruebas destructivas contra la base principal. Una restauración exige destino vacío, API/trabajador detenidos y termina pausando la automatización. Las copias, secretos y datos sincronizados no se suben al repositorio. El [contexto anterior](archive/contexto_ia.md) es historia del producto; no sustituye estas instrucciones ni las del usuario.
